# Compatibility with OUI-APEX

OUI-SNITCH is a fork of [OUI-APEX](https://github.com/lukeswitz/oui-spy-unified-blue),
which builds on the OUI-SPY engines by
[colonelpanichacks](https://github.com/colonelpanichacks).

**Short version: do not mix the two.** Run OUI-SNITCH firmware with the
OUI-SNITCH app, and OUI-APEX firmware with the OUI-APEX app. The link between
board and phone has diverged, and the mismatch is silent — nothing errors, the
app simply reports the wrong things.

---

## What still works across both

- **The build system.** Same PlatformIO layout, same `v3_app_controlled`
  environment, same board definitions. An OUI-APEX build recipe works here.
- **The hardware.** Any board OUI-APEX runs on runs this, with the same pinout.
- **The BLE service shape.** Same UUID base, same characteristic numbering
  scheme. A generic BLE explorer sees a familiar device.
- **WiGLE CSV output.** Unchanged format; both upload to the same place.
- **The engine concept.** Engines are still a bitmask the app sets, started and
  stopped the same way.

That shared shape is exactly why mixing them is dangerous: the two will
connect, pair, and appear to work.

---

## Where they differ

### 1. Wire identifiers collide

Both projects renumbered the same identifiers, independently and
incompatibly. These values are the protocol, shared between firmware, app, and
any mesh node:

| Identifier | OUI-APEX | OUI-SNITCH |
|---|---|---|
| engine slot 1 | `ENGINE_FLOCK_BLE` | `ENGINE_AXON` |
| `SIG 0x02` | `SIG_FLIPPER` | `SIG_HACKTOOLS` (Flipper + Pwnagotchi) |
| `SIG 0x10` | `SIG_PWNAGOTCHI` | `SIG_MESH` (Meshtastic, MeshCore) |
| `SIG 0x7F` / `0xFF` | `SIG_ALL = 0x7F` | `SIG_ALL = 0xFF` |
| `METHOD_DET 10` | `METHOD_DET_AMAZON` | `METHOD_DET_EVILTWIN` |
| `METHOD_DET 11` | — | `METHOD_DET_PINEAPPLE` |
| `METHOD_DET 12` | — | `METHOD_DET_MESH` |

`SIG_CAMERA = 0x80` and `METHOD_DET_CAMERA = 9` happen to agree, by coincidence
rather than coordination.

**Why this matters more than it looks.** These are separate lines in separate
files. Git merges all of them without raising a single conflict, and the result
compiles. An OUI-SNITCH board reporting `SIG 0x10` tells an OUI-APEX app it has
found a Pwnagotchi, when it has found a Meshtastic node. No layer anywhere
detects the disagreement.

A warning to this effect sits above `enum EngineId` in `src/protocol.h`.

### 2. The detector extension carries an extra byte

`DetectionEvent.ext.detector` gained a `confidence` field
(`DET_CONF_SUSPECTED` / `HIGH` / `VERIFIED`), letting the app alert only at or
above a tier the user picks instead of on every match.

Note that this payload is **custom-packed in `ble_gatt.cpp`**, not a raw struct
copy, so the C struct layout is not by itself the wire format. The app reads
`filter_desc` at `ext[0..31]`, `is_full_mac` at `ext[32]`, and `confidence` at
`ext[33]`.

### 3. The Flock BLE engine is gone

Its community BLE detection method stopped working; the Wi-Fi IE fingerprint is
the reliable path. The engine was removed and **its wire ID held reserved**, so
engine IDs and bitmasks would not shift — they are shared with mesh nodes that
may run other builds. Slot 1 now holds a dedicated duty-equipment engine.

### 4. Characteristics and commands only here

| Added | Purpose |
|---|---|
| `CHR_PAIRING` (`0x26`) | Read/write the pairing passkey over an already-paired link |
| `CHR_ENOW_CORE` (`0x27`) | Hub for third-party ESP-NOW wardriving nodes |
| `SYS_CMD_RING_TRACKER` (`0x0D`) | Make a found tracker play its sound |
| `SYS_CMD_POWER_OFF` (`0x0E`) | Deep sleep until physical reset |
| `OUISPY_BLE_PROTO_VERSION` | So the app can refuse or degrade loudly after a firmware update instead of misparsing |
| `g_bootEpoch` / `g_bootCount` | Tell "the link blipped" from "the board restarted" on reconnect |
| `g_activeProbeEnabled` | Global transmit gate — see below |

## What OUI-SNITCH adds

### Detection

- **Camera / surveillance signature** (`SIG_CAMERA`) — IEEE-registry camera
  vendor OUIs plus name and SSID patterns, with confidence tiers. The OUI table
  is generated by `tools/gen_camera_oui.py`, so it can be regenerated from the
  primary source rather than hand-maintained.
- **Real follow-detection for trackers.** Samsung SmartTag, Tile and Google
  Find My added alongside Apple. More importantly, "following" now means
  something: tiers for *nearby*, *following* (sustained over 5 minutes) and
  *returning* (3 windows in 10 minutes). The previous behaviour alerted after
  three seconds of proximity and called that following.
- **Duty-equipment detection widened** beyond one vendor to 18 registry OUIs,
  with Axon rated HIGH and the rest SUSPECTED, and given its own engine on the
  freed slot — its own tile, radio slice and buzzer.
- **Evil-twin and KARMA access points** — a concrete rule (one SSID beaconing
  from a second BSSID with a differing OUI; one BSSID announcing many SSIDs).
- **Mesh radios** — Meshtastic by service UUID, MeshCore by name.
- **Genetec ALPR**, Apple Continuity TLV chain parsing, and Skydio in both the
  drone and duty-equipment paths.
- **Confidence tiers end to end**, with a user-set alert threshold in the app.

### Privacy and safety posture

- **Passive by default.** Wardrive no longer transmits probe requests unless the
  user opts in. The gate (`g_activeProbeEnabled`) is deliberately global rather
  than per-engine, because more than one engine has its own probe routine and
  gating only one leaves the device transmitting while the UI says it is
  listening.
- **Pairing required** for the phone link, with a settable passkey.
- **A privacy screen** that masks identifiers in the UI.
- **Android backup disabled**; detection logging gated to debug builds.
- **Runs under GrapheneOS's** dynamic-code-loading restriction.
- **In-app firmware OTA disabled**, and WiGLE donation made an explicit choice.
- **Ignore list persisted** across reboots in NVS.

### Reliability

- **Link recovery through the OS.** Reconnect uses Android's own GATT
  auto-connect, so the connection completes the moment the board advertises
  again, instead of waiting out an app-side retry ladder. A watchdog also
  notices a link that is nominally up but silently dead.
- **Spooled detections are no longer lost**, and a wedged Wi-Fi sniffer is
  detected and cycled — using a per-engine frame counter, because the global
  one every engine increments cannot reveal a Wi-Fi-only stall.
- **A wardrive that loses its board** gets a bounded five-minute resume window;
  past it the session is ended, saved and announced, rather than left showing
  "running" over a link recording nothing.
- **One way in and one way out of a session.** Starting a wardrive goes through
  a single path, so a target selected on the map is no longer discarded by
  starting from the home tile.
- **One marker per device on the map**, positioned by the strongest sighting, so
  position and signal come from the same sample; dense areas genuinely cluster
  instead of snapping to a grid.

### Other

- **ESP-NOW hub for third-party wardriving nodes**, with a hard rule that the
  hub never scans while hubbing.
- **Offline archive analysis** and user-triggered WiGLE lookups reusing the
  existing login.
- **Tracker ring** — make a located tracker play its sound.
- **MIT licence** applied, with per-file markers and
  [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md) recording what is vendored
  under other terms.

## For contributors

When adding a protocol identifier, **take the next free value in this
repository** without regard for what upstream did with it. Compatibility was
given up deliberately. It is not something a later change can quietly restore,
and a change that appears to restore it is almost certainly a bad merge.

Features may be ported from OUI-APEX by hand. They must never arrive by merge.
